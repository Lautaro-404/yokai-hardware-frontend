Especificación Técnica y Creación de
Base de Datos PostgreSQL 15+

Esquema relacional en Tercera Forma Normal (3FN) para la tienda Yokai Hardware. Diseñado para soportar control de stock atómico anti-overselling, compatibilidad de hardware vía JSONB, auditoría automática, versionado con Flyway e integración estricta con Spring Boot 3 / Hibernate 6.

Motor: PostgreSQL 15+ (Alpine / Render / Neon) Migraciones: Flyway V1..V7 + Seeds JPA ddl-auto: validate Moneda: NUMERIC(12, 2) ARS ↔ BigDecimal Tests: Testcontainers + JUnit 5
01

Decisiones de Arquitectura Resueltas (ADR)

Decisiones tomadas según el plan aprobado y su justificación técnica para el e-commerce.

Decisión 1

Máquina de Estados de Pedido

Ciclo de vida lineal: PENDIENTE_PAGO → PAGADO → EN_PREPARACION → ENVIADO → ENTREGADO (+ CANCELADO). Se descarta separar en flags booleanos para evitar condiciones de carrera.

Decisión 2

Carrito Híbrido

Usuarios anónimos almacenan ítems en LocalStorage; al autenticarse, sincronizan a carrito_item. No se sobrecarga la base con carritos abandonados.

Decisión 3

Atributos JSONB & GIN

Uso de columna JSONB en producto para atributos técnicos variables (sockets, TDP, milímetros), indexado con GIN y B-tree de expresión, evitando el antipatrón EAV.

Decisión 4

Anti-Overselling Atómico

UPDATE condicional WHERE stock >= :cantidad. Si las filas afectadas son 0, se gatilla rollback total. Sin locks pesimistas extensos ni reintentos optimistas fallidos.

Columna Generada Almacenada

producto.estado_stock

Calculada nativamente en disco por PostgreSQL: CASE WHEN stock = 0 THEN 'SIN_STOCK' WHEN stock <= stock_minimo THEN 'ULTIMAS_UNIDADES' ELSE 'EN_STOCK' END. No requiere código Java para sincronizarse.

Inmutabilidad Histórica

detalle_pedido.precio_unit

Al realizarse el pedido, se congela el precio unitario exacto en NUMERIC(12,2). Modificaciones futuras al precio de catálogo no alteran los pedidos pasados.

Soft Delete & Integridad

producto.activo & RESTRICT

Claves foráneas con política ON DELETE RESTRICT hacia producto e historial de compras. Los productos eliminados pasan a activo = false filtrados vía @SQLRestriction.

-- Validador de especificaciones JSONB por categoría para CompatibilidadEngine
CREATE OR REPLACE FUNCTION validar_especificaciones_producto()
RETURNS TRIGGER AS $$
DECLARE
    v_categoria_nombre VARCHAR(50);
    v_specs JSONB;
BEGIN
    SELECT nombre INTO v_categoria_nombre FROM categoria WHERE id = NEW.categoria_id;
    v_specs := NEW.especificaciones;

    CASE
        WHEN v_categoria_nombre = 'Oni' OR v_categoria_nombre ILIKE '%GPU%' THEN
            IF NOT (v_specs ? 'tdp_w' AND v_specs ? 'length_mm') THEN
                RAISE EXCEPTION 'GPU requiere "tdp_w" y "length_mm" numéricos en JSONB. SKU: %', NEW.sku;
            END IF;
        WHEN v_categoria_nombre = 'Kitsune' OR v_categoria_nombre ILIKE '%CPU%' THEN
            IF NOT (v_specs ? 'socket' AND v_specs ? 'tdp_w') THEN
                RAISE EXCEPTION 'CPU requiere "socket" y "tdp_w" en JSONB. SKU: %', NEW.sku;
            END IF;
        WHEN v_categoria_nombre ILIKE '%Motherboard%' OR v_categoria_nombre ILIKE '%Placa Madre%' THEN
            IF NOT (v_specs ? 'socket') THEN
                RAISE EXCEPTION 'Placa Madre requiere "socket" en JSONB. SKU: %', NEW.sku;
            END IF;
        WHEN v_categoria_nombre ILIKE '%Fuente%' OR v_categoria_nombre ILIKE '%PSU%' THEN
            IF NOT (v_specs ? 'watts') THEN
                RAISE EXCEPTION 'Fuente requiere "watts" numérico en JSONB. SKU: %', NEW.sku;
            END IF;
        WHEN v_categoria_nombre ILIKE '%Gabinete%' OR v_categoria_nombre ILIKE '%Case%' THEN
            IF NOT (v_specs ? 'max_gpu_mm') THEN
                RAISE EXCEPTION 'Gabinete requiere "max_gpu_mm" en JSONB. SKU: %', NEW.sku;
            END IF;
        ELSE NULL;
    END CASE;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trg_validar_especificaciones_producto
    BEFORE INSERT OR UPDATE OF especificaciones, categoria_id ON producto
    FOR EACH ROW EXECUTE FUNCTION validar_especificaciones_producto();

Reglas Matemáticas del CompatibilidadEngine

1. Socket Matching

cpu.socket == mb.socket
Ej: Ryzen 7800X3D (AM5) empareja con ASUS B650E-F (AM5). Falla con Z790 (LGA1700).

2. Margen de Fuente

psu.watts >= (cpu.tdp + gpu.tdp) * 1.25
Ej: 4090 (450W) + 14700K (253W) = 703W * 1.25 = 878.75W. Falla en 650W/850W; requiere 1000W.

3. Espacio Físico GPU

gpu.length_mm <= case.max_gpu_mm
Ej: Strix 4070Ti (336mm) entra en O11D (426mm); rechazada en chasis ITX A4-H2O (322mm).

Estructura normalizada en JSONB (Oni GPU vs Gabinete):

  "tdp_w": 285,

  "vram_gb": 16,
  "memoria_tipo": "GDDR6X",
  "power_connector": "16-pin 12VHPWR",
  "slots": 3.15

Estrategia Anti-Overselling & Consultas Críticas

Descuento atómico a nivel de motor en la transición a PAGADO.

UPDATE Condicional Anti-Overselling

Descuenta stock en 1 sola sentencia atómica. Si rows_affected == 0, significa que no había stock o el producto fue dado de baja, provocando rollback inmediato: 

-- db/queries/consultas_clave.sql (Query Anti-Overselling)
UPDATE producto 
SET stock = stock - :cantidad_solicitada,
    updated_at = CURRENT_TIMESTAMP
WHERE id = :producto_id
  AND activo = true
  AND stock >= :cantidad_solicitada;
Protección contra Deadlocks: El servicio Java procesa las líneas del pedido ordenadas ascendentemente por producto_id antes de ejecutar los UPDATEs.

Catálogo Facetado con Keyset Pagination

Aprovecha el índice compuesto idx_producto_catalogo_facetado y evita el costo de OFFSET: 

SELECT p.id, p.sku, p.nombre, p.precio, p.stock, p.estado_stock,
       c.nombre AS categoria, m.nombre AS marca, p.especificaciones
FROM producto p
JOIN categoria c ON p.categoria_id = c.id
JOIN marca m ON p.marca_id = m.id
WHERE p.activo = true
  AND (:categoria_id IS NULL OR p.categoria_id = :categoria_id)
  AND (:marca_id IS NULL OR p.marca_id = :marca_id)
  AND (:precio_min IS NULL OR p.precio >= :precio_min)
  AND (:precio_max IS NULL OR p.precio <= :precio_max)
  AND (:ultimo_precio IS NULL OR (p.precio > :ultimo_precio OR (p.precio = :ultimo_precio AND p.id > :ultimo_id)))
ORDER BY p.precio ASC, p.id ASC
LIMIT 12;

Entidades JPA & Hibernate 6 (Spring Boot 3)

Mapeos nativos de Hibernate 6 sin dependencias externas obsoletas.

Producto.java (Hibernate 6.3+) 
@Entity
@Table(name = "producto")
@SQLRestriction("activo = true") // Reemplazo moderno de @Where
public class Producto {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(name = "precio", nullable = false, precision = 12, scale = 2)
    private BigDecimal precio;

    @Column(name = "stock", nullable = false)
    private Integer stock = 0;

    // Columna generada por PostgreSQL calculada automáticamente
    @Column(name = "estado_stock", insertable = false, updatable = false)
    private String estadoStock;

    // Mapeo nativo de JSONB en Hibernate 6
    @JdbcTypeCode(SqlTypes.JSON)
    @Column(name = "especificaciones", columnDefinition = "jsonb")
    private Map especificaciones = new HashMap<>();

    @Column(name = "activo", nullable = false)
    private Boolean activo = true;
}
ProductoRepository.java 
@Repository
public interface ProductoRepository extends JpaRepository {

    @Modifying
    @Query("""
        UPDATE Producto p
        SET p.stock = p.stock - :cantidad,
            p.updatedAt = CURRENT_TIMESTAMP
        WHERE p.id = :id
          AND p.activo = true
          AND p.stock >= :cantidad
    """)
    int descontarStock(@Param("id") Long id, @Param("cantidad") Integer cantidad);

    @Modifying
    @Query("""
        UPDATE Producto p
        SET p.stock = p.stock + :cantidad,
            p.updatedAt = CURRENT_TIMESTAMP
        WHERE p.id = :id
    """)
    int restituirStock(@Param("id") Long id, @Param("cantidad") Integer cantidad);
}
